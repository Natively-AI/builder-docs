App secrets — also called environment variables — are values your app's server-side code needs at runtime: third-party API keys, service tokens, or config that shouldn't live in your source code or be typed into chat.

## What they're for

If your app calls a third-party API, needs a service token, or reads a config value that differs between environments, that value belongs in app secrets, not hardcoded in a file or pasted into a chat message. Your app's server-side code can read it; the value itself isn't part of your code and isn't visible in the chat history.

## Add or edit a secret

<Steps>
  <Step title="Open project settings">
    Open your project and go to its **Settings**.
  </Step>
  <Step title="Go to Environment Variables">
    Select the **Environment Variables** tab (next to **Domains**).
  </Step>
  <Step title="Add a variable">
    Click **Add variable**, enter a key (for example `KEY_NAME`) and its value, and save.
  </Step>
  <Step title="Edit or remove later">
    Come back to the same tab any time to update a value or remove a variable your app no longer needs.
  </Step>
</Steps>

<Note>
  App secrets are scoped **per project**. If two projects both need the same key, add it to each project separately.
</Note>

<Warning>
  Saving a new value under an existing key replaces the old one. There's no undo — double-check before you overwrite a value another part of your app depends on.
</Warning>

## App secrets vs. Supabase's own secret handling

These are two separate mechanisms, and it's worth knowing when each applies:

- **App secrets** (this page) are values *you* set proactively in project **Settings → Environment Variables**. They're for your app's own server-side code in general — any API key or config value your project needs, Supabase-related or not.
- **Supabase's masked-prompt flow** is different: when the **Builder agent** needs a secret specifically for something it's building with Supabase, it asks for it inline in chat through a masked input, and that value is stored in **Supabase's** own secret storage, not in your project's Environment Variables tab. See [How the agent handles secrets](/features/supabase#how-the-agent-handles-secrets) for that flow.

In short: use Environment Variables for values you're adding yourself; the agent will ask you separately, through the masked-input flow, for anything it needs specifically for Supabase.
